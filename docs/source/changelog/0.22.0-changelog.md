# v0.22.0

Date
: October 06, 2026


## Highlights 🌟

### Unified output selection and configurable video encoding

Choosing what Manim produces has been reworked around a single `format`
setting. `--format` (or `format` in the `[CLI]` section of a config file)
selects exactly one primary artifact: `auto` (the default; MP4, or MOV for
transparent output), `mp4`, `mov`, `webm`, `gif`, `png` (last frame only),
`png-sequence` (every frame), or `none` (evaluate the scene without writing
media). It replaces the overlapping `--write_to_movie`, `-g`/`--save_pngs`,
`-i`/`--save_as_gif`, and `--force_window` options. Viewing the result is now
separate from choosing what to write: `-p`/`--preview` opens the finished file
with either renderer, while `-l`/`--live-preview` shows a live window (OpenGL).
As a consequence, the OpenGL renderer now writes files by default, just like
Cairo. Output paths are resolved up front, media directories are only created
when something is written to them, and the `--custom_folders` preset has been
removed in favor of the regular directory settings. ({pr}`4966`, {pr}`4969`)

Video encoding is now configurable, too: the new `[video_encoder]` config
section and the `--video-codec`, `--pixel-format`, and repeatable
`--encoder-option KEY=VALUE` options control how partial movie files are
encoded, for example
`manim render --video-codec libx264 --encoder-option crf=18 --encoder-option preset=slow scene.py`.
Encoder settings are part of the cache key, so changing them no longer reuses
incompatible cached segments, and the new `manim cache clear` command replaces
the `--flush_cache` flag. ({pr}`4976`)

Scenes rendered with default settings need no changes, but scripts and config
files relying on the removed options have to be updated. See the migration
notes in the Breaking Changes section below, as well as
{doc}`/guides/configuration` and {doc}`/tutorials/output_and_config`.

### A `Manager` for coordinating the render flow

Every `Scene` is now accompanied by a {class}`.Manager` that coordinates its
render cycle: setup and construction, play timing, sections, subtitles, audio,
and presenting the finished output. Drawing and encoding are still delegated
to the existing Cairo and OpenGL renderers and the file writer, and regular
scenes do not need any changes. Until now, these responsibilities were spread
across `Scene`, the renderers, the camera, and the file writer; the `Manager`
gives them a single owner. This release lays the groundwork, and upcoming
releases will build on it to move rendering execution and output ownership
into the `Manager` and to remove the remaining cross-dependencies between
scenes, renderers, and file writing. The {doc}`/guides/deep_dive` has been updated to
describe the new flow. ({pr}`4916`)
